## Intent

**Problem:** Diagnostic bundles identify resource bytes but cannot identify the complete effective 500T recipe or establish what color interpretation the LUT requires. Later rendering work could apply a delivery transform twice or use Apple Log values with an incompatible LUT.

**Approach:** Define a versioned recipe with explicit input, LUT, effect and delivery contracts, retaining the existing Apple Log 2 LUT assets and approved capture behavior. Record its effective values and provenance in diagnostics and set the writer bitrate target to 36 Mbps while preserving source dimensions and orientation (4K sources remain 4K).

## Boundaries & Constraints

**Always:** Preserve unrelated staged and unstaged work. Preserve Apple Log 2 capture preference and fallback, immediate locked white balance, direct Resolve RGB/red-fastest LUT upload, removed arbitrary contrast mapping, resource bytes, ISO selection, and existing film-stock/ISO/halation movie metadata. Record the effective configuration after a shot's ISO override. Keep app and CLI recipe definitions consistent.

**Never:** Invent a LUT output transfer function from its filename or numeric range. Apply additional decoding, delivery conversion, sampler changes, spatial effects, grain changes, audio fixes, or camera/UI changes in this contract story. Treat an untagged synthetic chart as a real Apple Log camera fixture or treat a CPU interpolation baseline as visual acceptance.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|----------------------------|----------------|
| Valid recipe | Declared recipe with valid effective effect settings | Diagnostic bundle identifies recipe version, color contract, LUT hash, and all effective parameters | No error expected |
| Recipe revision | Same source and resources, revised declared recipe version | Bundle identifies the changed recipe independently of resource hashes | No error expected |
| Unknown provenance | LUT export interpretation unavailable | Evidence explicitly records unverified domains; no claim of verified Rec.709 delivery | Prevent contract lock and dependent color implementation |
| Invalid recipe | Unsupported version, nonfinite values or invalid parameters | Configuration failure identifies the offending recipe | No successful render reported |
| Per-shot override | Same stock with two selected ISO values | Each diagnostic records its own effective ISO and otherwise identical recipe | No error expected |

**Decision (2026-10-09):** User does not know the LUT output. Proceed with versioning/diagnostics and record it as unverified. Expected input is Apple Log 2; delivery request is 4K HEVC/H.265 at medium bitrate, accepted starting target 36 Mbps. Do not add a color conversion or assert calibrated Rec.709 output. Deterministic color chart reference and verified color transforms remain deferred pending provenance/reference evidence. User approved implementation with “ok go”.
