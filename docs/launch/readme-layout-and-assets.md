# README landing-page layout — awaiting author copy

Working layout, **not replacement product copy**. The existing root README is unchanged until the author supplies the words. Do not publish this checklist as the landing page.

## Proposed reading order

1. **Nitrate + one sentence** — author writes what it is and who it is for.
2. **Actual footage** — one short, owned demo; linked playable video with a still fallback for GitHub. No simulated product output, synthetic footage or invented testimonial.
3. **One primary action** — TestFlight invitation when approved and verified; later replace with the live App Store link. Until then, no fake badge, dead link or claim of availability.
4. **Why I made it** — author copy, preserved verbatim unless edits are requested.
5. **What shooting with it is like** — author copy, not a generated list of aspirations.
6. **A few examples** — original clips, actual stock/gauge, basic shot context. Permissions and credit recorded before reposting.
7. **Compatibility / beta limitations / pricing** — factual block checked against the release binary and approved account data, not promotional claims. Do not bury device requirements beneath the CTA.
8. **Privacy / support / technical notes / source rights** — short navigation to detailed pages.

## Refactor steps after copy arrives

- Preserve the current README in a technical reference before moving content; repair relative links after relocation.
- Separate architecture/build/LUT/grain detail from the primary landing page. Keep provenance and licences easy to find.
- Audit every retained claim against the current app. Existing copy is not automatically valid: current README contains strong retention/privacy/recovery language and preview descriptions that must be reconciled with the launch review.
- Insert author copy without unsolicited rewriting; show any suggested edits separately.
- Add authentic demo media and a verified beta CTA. No empty image paths or unapproved external links.
- Preview GitHub Markdown at phone and desktop widths; check anchors, repository-relative links, video fallback and the compatibility block.
- Obtain author approval before replacing the public-facing README or publishing it.

## Asset brief (capture once, reuse)

Proposed minimal owner session: 20–30 minutes with the phone after launch-blocking fixes.

- 4–6 actual Nitrate clips: daylight people/skin, tungsten interior, moving detail, highlights/night, a slow tele zoom, and one longer ambient scene for audio.
- Save untouched rendered files plus the corresponding original Log where available; record app build, stock, gauge, lighting and delivery setting.
- One screen recording: select stock → record → render queue → saved result. Do not label accelerated render time as real time.
- Avoid recognisable bystanders, copyrighted music and location details unless you have permission to publish them. Record consent/ownership.
- Agent can cut owned source clips into a hero demo, social variants and stills after originals are supplied; no invented footage and no claim that a mockup is the app.
